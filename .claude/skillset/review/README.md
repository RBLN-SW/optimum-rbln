# 룰 리뷰 안내

> **응답은 공유 리뷰 페이지에서 해 주세요:** https://claude.ai/artifact/2LTDRgqHMaqRub2NoNcUpZ (링크가 열리지 않으면 공유 요청). 이 폴더의 마크다운 시트는 같은 내용의 오프라인 사본이며, 아래 안내는 둘 다에 해당합니다.

optimum-rbln의 "구전 룰"을 PR 본문·리뷰 코멘트에서 채굴하고 현재 코드(dev)와 대조한 결과입니다. 이 폴더의 영역별 파일을 **담당 영역만** 읽고 응답해 주시면 됩니다. 한 영역에 10~25개, 룰당 30초, 전체 10~15분을 넘지 않게 만들었습니다.

## 한 룰의 생김새

```
### CFG-005 · 결정 필요
**룰** rbln_config에는 컴파일 그래프를 바꾸는 값만 두고 런타임 전용 값은 분리한다.
**조건** 런타임 전용 값은 create_runtimes, device, device_map, activate_profiler, timeout.
**근거** #67 (jongho): "…원문 인용…"
　　　#702 (seinpark): "…원문 인용…"
**코드 대조** 코드 일치 — 준수 10 / 위반 0
**질문** 런타임 전용 옵션을 rbln_config 객체에 담을 수 있게 둘지, from_pretrained 인자로만 받을지?
**응답** [ ] 맞다 　[ ] 틀리다 　[ ] 조건부로 맞다 　[ ] 필요 없는 룰이다 　[ ] 모른다 　[ ] 기억나지 않는다 　· 메모:
```

- **룰** 한 문장. 이것이 리뷰 대상입니다.
- **근거** 실제 PR·리뷰 코멘트의 원문 인용(글자 그대로)과 링크. 룰이 어디서 나왔는지 확인용입니다. 인용이 룰을 뒷받침하지 않는다고 보이면 "틀리다"에 그 이유를 적어 주세요.
- **코드 대조** 현재 dev 코드가 이 룰을 따르는지 센 결과입니다. "코드 불일치"는 룰이 틀렸다는 뜻이 아니라, 팀이 룰로 채택하면 고칠 코드가 있다는 뜻입니다.
- **질문** "결정 필요" 룰에만 있습니다. 근거가 서로 반대이거나 코드에 두 방식이 공존해, 어느 쪽인지 팀이 정해야 합니다.

## 응답 방법

`[ ]` 하나를 `[x]`로 바꿔 주세요.

| 응답 | 뜻 |
|---|---|
| 맞다 | 우리 룰이다. 새 코드에 적용해도 된다. |
| 틀리다 | 룰이 아니거나 반대다. **메모**에 한 줄 이유. |
| 조건부로 맞다 | 특정 조건·영역에서만 맞다. **메모**에 조건. |
| 필요 없는 룰이다 | 맞고 틀리고를 떠나 굳이 룰로 정할 필요가 없다(당연하거나, 드물거나, 도구가 이미 막는다). **메모**에 이유 한 줄. |
| 모른다 | 이런 룰이 있는지 몰랐다. (룰이 공유 지식이 아니라는 신호. 틀렸다는 뜻이 아님) |
| 기억나지 않는다 | 정했던 것 같은데 지금은 모르겠다. (결정이 유실됐다는 신호) |

"모른다"와 "기억나지 않는다"는 솔직하게 골라 주세요. 둘은 집계가 다릅니다. 전자가 많으면 문서화가 필요한 룰이고, 후자가 많으면 원래 결정을 찾아야 하는 룰입니다.

추가로, 룰을 어기는 코드를 알고 계시면 **메모**에 파일명만 적어 주세요.
