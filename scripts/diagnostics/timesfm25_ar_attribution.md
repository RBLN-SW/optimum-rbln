# TimesFM2.5 raw and autoregressive feedback attribution

This B1 diagnostic investigates the existing CI792 failures without changing the original `timesfm25_native_core.py`, its six native fixtures, or its acceptance thresholds. CI792 remains a failed baseline. The focused attribution cases are native 15360+h1024 and the failing positive row of the mixed positive-falling native 16256+h128 fixture.

Every learned input projection, transformer layer, normalization/scaling weight and forecast head remains in the compiled NPU core: all 231,289,280 learned parameters. The CPU copy is a diagnostic oracle only. The teacher-forcing path is a counterfactual experiment and cannot establish product acceptance or justify learned CPU offload.

The script runs the original free forecast, an independently traced free forecast, and a traced teacher-forced forecast using the same runtime. In both traced paths the final forecast aggregates actual runtime point/spread outputs. Free-running appends the runtime median after native RevIN; teacher forcing appends the CPU oracle median after the same running-statistics inverse. Both signs preserve the entire normalized prefix and update running statistics patch by patch. All four inputs retain their original-max shapes: tokenizer `[1,512,64]`, additive mask `[1,1,512,512]`, cos/sin each `[1,512,80]`.

Before each runtime call, the script snapshots the exact input tensors. It evaluates the CPU core on that snapshot and saves the inputs, actual runtime raw outputs, same-input CPU raw outputs and running count/mean/std **before computing metrics**. Output buffers are cloned before another runtime call can reuse them. Each trace reports raw point/spread error overall, per field, per 128 positions, and the denormalized feedback median error. It records prefix length, leading padding, final valid token index 511, its adjusted position ID, final patch value range, and input immutability. The paired-path report compares normalized prefix values, the last four valid patches, running statistics and CPU output drift, with exact mask/cos/sin equality controls.

These measurements distinguish instantaneous core error on identical inputs from differences introduced by previously fed-back values and statistics. A smaller teacher-forced final error supports feedback amplification as a mechanism. It does **not** prove that the initial core error is acceptable arithmetic approximation or exclude a mask/shape-dependent device kernel defect. Large or step-dependent same-input raw errors require further kernel investigation. The falling h128 case has no autoregressive append; teacher forcing cannot repair it through feedback, and both paths should retain its failure under deterministic execution.

Only original free-running native point and quantile results use the unchanged acceptance gate: finite, NRMSE<=.05 and PCC>=.99, with constant-reference absolute error<=1e-6. The final assertion still fails when the baseline fails regardless of teacher-forced results. Teacher-forced NPU errors are descriptive and have no acceptance flag; the report always records `product_accepted: false`. Traced free execution must also equal the original free forecast exactly. The original same-input raw and repeated execution checks remain present. Cold/warm runtime timings and per-call trace timings include host invocation and output copies; they are not device-only latency measurements.
